# Scope and limitations

CoRe is a controlled evaluation protocol, not a new cleaning algorithm. Its frozen results concern eight main-comparison LLMs, three controlled data families and a separate Rayyan reference audit, on English tables concerning mainly US entities. Hospital's damaged names, Movies' source-specific mappings and retained candidates, Beers' information-preserving formatting errors, and Rayyan's reference transformations provide complementary diagnoses. The selection supports mechanism-specific interpretation, not a prevalence estimate across cleaning workloads. Transfer to private data also depends on size, sparsity, task complexity and supporting records. The [claim map](../paper/claim-map.md) states the supported conclusions.

Original, word and syllable conditions pair rows and error positions; fresh records can differ in difficulty. Hospital F largely revisits the same institutions in a newer source. Beers F differs in brewery concentration and alcohol-content distributions, so it is descriptive. Name substitutions also change surface form. Hospital's restricted syllable inventory is partly recoverable by GPT-6.1-Sol. The tables retain one accepted error-strength exception, documented in the [construction companion](../paper/CoRe-Supplementary-Technical-Report.pdf#nameddest=companion-1).

The continuation probe found no positive evidence of benchmark-row memorization in the tested models and samples. This is not proof of absent memorization or training contamination. Original-minus-fresh differences are not a pure memorization estimate. Movies knowledge claims rely on the commercial models because open-model repair scores are near zero. The scale trend concerns Qwen2.5's total Hospital effect. Beers is a model-dependent boundary case. Knowledge conflicts mainly affect attributes with distinctive real-world values, such as film directors; they do not measure how often such conflicts occur in private data.

Intervals summarize fixed constructions and archived replies, not repeated API calls. Chunk resampling does not separately estimate dependence between chunks sharing an entity. Entity resampling in conflict tests leaves shared-chunk dependence outside its uncertainty estimate. Whole-table methods receive supporting records unavailable in the main chunk setting.

The default Movies display uses numerical witnesses; raw Movies records and replies remain outside the Git tree and statistical core. The optional historical ZIP is a [separate Release asset in the same private GitHub repository](github-delivery.md), not a public data release or proof of reviewer access or data rights. Its exact historical route re-scores archived cleaning and conflict outputs, while the new [continuation scorer](continuation-scoring.md) rejudges saved replies and the [baseline scorer](baseline-scoring.md) checks saved corrections and final tables. With exact historical inputs these cover 168 continuation archives, 13 TabClean conditions, 72 whole-table correction lists and 59 aligned archives. Twelve whole-table runs have counts but no saved correction lists; the server, checked backups and logs did not recover them. One earlier unseeded Movies-fresh aligned archive has stale row metadata and is not selected for the paper's seeded comparisons.

Raw continuation rejudgment exposes a separate scoring-version issue: twelve early DeepSeek summaries differ from the present bound scorer in 253 fields concerning hard cells and structural baselines. Reconstructed older scoring behavior is compatible with the saved summaries, but its source revision was not recovered. Current display uses the separately bound uniform integer reanalysis; original archives and frozen display remain unchanged. The full-table screen subtracts target votes but is not strict row-held-out refitting; clean-value leakage uses the clean full table and predecessor. It can exclude genuine memory and has no calibrated detection-power or memory-prevalence interpretation. See the [exact field and manuscript impact](continuation-scoring.md#observed-archived-scoring-convention-difference-2026-10-26). These checks neither establish complete historical recovery nor reviewer access. [Data instructions](data.md) and the [coverage matrix](../REPRODUCTION.json) identify acquisition and execution routes separately.

Rayyan replay uses saved title matches, retained field-check outcomes and saved encoding outcomes. It includes 114 scalar rechecks but does not reconstruct the full PubMed candidate responses or all encoding checks. The 95.2% estimate (95% interval 91.2–97.8%) is a weighted reference-check failure rate among title-matched sampled cells under field-specific criteria, using the 948-cell type composition. It is not the fraction of erroneous literature records. Its interval conditions on the saved matches and checks and excludes matching uncertainty and PMID-level dependence. Date checks test agreement with publication year despite undocumented exact field semantics; volume/issue checks test presence. See the [Rayyan companion](../paper/CoRe-Supplementary-Technical-Report.pdf#nameddest=companion-3).

Reproducing the archived statistics does not make a fresh model run identical or establish external correctness for every reference cell. The study's experiment scope and raw evidence remain frozen; the current limited reanalysis corrects continuation display and two Beers adjusted probabilities without new models, datasets, seeds or generated replies.
